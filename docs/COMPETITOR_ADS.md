# Competitor ads (`python -m etl.competitor_ads`)

Weekly, unattended: what competitors run on Meta right now, classified into Lonvera's taxonomy. Feeds the Creative priorities one-sheeter through the view `competitor_concepts`.

## Method (and what does not work)
- **Meta Ad Library API (`/ads_archive`): not usable.** With our token it answers error 10 / subcode 2332002 "Application does not have permission for this action" (identity confirmation for the Ad Library API is required, and it does not serve commercial US ads anyway). Checked 2026-11-09.
- **Works: headless Chromium (Playwright) on the public Ad Library page**, no login: `ads/library/?active_status=active&country=US&q="<phrase>"&search_type=keyword_exact_phrase&sort_data[mode]=total_impressions`. Scrolls (2.2 s pauses) until ~150 cards, 6 s between searches. Chromium is installed in the Dockerfile (`PLAYWRIGHT_BROWSERS_PATH=/ms-playwright`).
- `view_all_page_id` lookups return "No ads match" headless for the page ids visible in cards, so brands are found by exact phrase (brand name, landing domain) and filtered by an advertiser-name regex; creator ads "X with Brand" are dropped.
- No paid scraper is used. No cost beyond Claude plan usage for classification.

## Flow
1. `competitor_brands` (editable; seeded from `BRANDS` in `etl/competitor_ads.py`): search phrases + `name_match` regex. Add a brand by inserting a row.
2. Each run writes `competitor_ads` (one row per Library ID per week, `week_start` = Monday Pacific). A brand that fails (wall, age gate, zero cards without an empty-result message) keeps its last good rows, copied forward with `carried_from` set; the view shows `is_stale`.
3. New `concept_key`s (brand + hash of the first 160 characters of normalised copy) are classified by headless Claude (`CLAUDE_CODE_OAUTH_TOKEN`, text only, 8 concepts per call, cap `--limit` 150): an existing line, `NEW` (suggested cluster / ICP / pain point) or `OUT`. Cached in `competitor_concept_class`, never re-asked.
4. Nightly `scripts/deploy/run_etl.sh` calls `etl.competitor_ads --if-sunday` after `etl.amazon_mtd` and before `etl.auto_tag` (non-fatal).

## Limits
No spend, impressions or ROAS are visible. `days_running` (start date to the day read) and `variant_count` are the only strength proxies; start dates reset when a brand re-uploads. Each search is a top slice by impressions (about 150 cards), not a census. Format is video vs image only (carousels look like images). Classification sees copy text only, never the image or video.

## Competitors page and API (read only)
`/competitors` (Creative > Competitors) is the weekly, visual view of this data. Top to bottom: a Week picker, an All / Video / Image toggle and a Brand wall / Table toggle (all three live in the URL: `?week=YYYY-MM-DD&format=video|image&view=table`); a pulse strip of four numbers (brands watched, ads running now, new this week, longest-running ad in days); a closed "What changed this week" fold (up to 8 facts from SQL and Python, no model calls); **Worth a look**, a scroll-snap rail of 8 to 12 curated ad cards; the **Brand wall**, one tile per brand; **Angles across competitors**, a bar chart; and **News and Reddit** cards when `competitor_posts` exists.
- **Ad cards** show the stored thumbnail, or, when none is stored, the hook set large on a block tinted from a stable hash of the brand name (same brand, same colour), with a video / image badge. Clicking a card opens a lightbox (a `<dialog>`): bigger picture, full primary text and headline, landing page and Ad Library links, previous / next buttons, swipe, Esc and the arrow keys.
- **Worth a look** selection (server side, `_spotlight`): new ads from brands that surged (at least 3 new ads and at least 30% of what they run; one card per brand), ads running an angle Lonvera does not run (one per brand, up to 4), and the longest-running proven ads (at least 30 days, up to 5); never more than 2 cards per brand; interleaved; topped up with the next longest-running ads to at least 8; capped at 12. Each card carries its reason (`proven`, `new_angle`, `surge`, `longest`) and a badge ("469 days running", "Angle Lonvera does not run", "New this week").
- **Brand wall** tile: name, what it sells, active ads with the change against last week, up to 3 mini thumbnails (typographic minis when none stored, ads with an image first), a video / image split bar, and the most common angle as a chip (accent when Lonvera does not run it). Sort select: most ads, most new, longest running, most video. Click a tile and its detail opens in place under the row: a gallery of up to 12 curated ads (its longest-running plus up to 4 new this week, one per concept), an angles bar chart (angles Lonvera does not run in the accent colour), landing pages with counts and the brand's Ad Library link. The Table view keeps the old sortable table with the old text detail.
- `GET /api/competitors?week=&format=` returns `{weeks, week, prior_week, format, first_snapshot, notice, brands[], changes[], caveats[], pulse, spotlight[], angle_chart[]}` and, only when the table `competitor_posts` exists, `chatter[]` (top 10 posts by score that week). Each brand also has `thumbs[]` (up to 3: `library_id`, `thumb_url`, `hook`, `format`) and `top_angle`. `pulse` = `{brands, active_ads, new_ads (null on a first snapshot), longest_days, longest_brand, longest_ad_library_url}`. `angle_chart[]` = top 10 `{label, cluster, pain_point, ads, brands, is_new_angle, new_angle_label}` across all brands (out-of-category and unclassified ads are not angles).
- `GET /api/competitors/<brand>?week=&format=` returns `{gallery[], longest_running[], new_this_week[], new_count, angles[], landing_pages[], brand_ad_library_url}` and `chatter[]` (top 5, that brand) when `competitor_posts` exists. A `gallery[]` / `spotlight[]` card is `{library_id, brand, hook, headline, primary_text (first 700 characters), format, days_running, variant_count, landing_url, landing_domain, thumb_url, ad_library_url, angle, is_new_angle, new_angle_label, badge, reason}`.
- `video_url` (same places as `thumb_url`: spotlight / gallery cards and the brand tile `thumbs[]`) is `/api/competitors/video/<library_id>` only for a video ad that has a row in `competitor_ad_video` (migration 257); `to_regclass` check plus LEFT JOIN, null otherwise, nothing errors when the table is absent.
- `thumb_url` is `/api/competitors/media/<library_id>` only when a row exists in `competitor_ad_media`; the query checks `to_regclass('public.competitor_ad_media')` and LEFT JOINs, so with the table absent or empty every `thumb_url` is null and nothing errors (the page then shows typographic cards). Thumbnails exist only for selected ads, so the curated lists (spotlight, gallery, tile strips) lead with those.
- `format` limits every number and every list (counts, new and stopped, pulse, spotlight, angle chart, gallery, angles, landing pages, the changes box) to that format. The Library only tells video from image, so carousels count as image.
- With one stored week, change / new / stopped are null, the new-this-week list is empty, there are no surge cards and the page says "First snapshot: changes start next week". A brand with no rows in the earlier week gets null changes too. Carried-forward (stale) rows have the same Library IDs as before, so they show no new or stopped ads and never count as a surge.
- Ad links are `https://www.facebook.com/ads/library/?id=<Library ID>`. Nothing calls Meta, Google or Reddit from the web process and nothing is written. Code: `app/competitors.py`, `app/static/js/pages/competitors.js` (page) and `competitors_cards.js` (cards, lightbox, bars), `app/static/css/competitors.css`.


### Learning layer (tags, transcripts, landing pages; `app/competitors_learn.py`)
Optional and silent: every table is checked with `to_regclass`; absent or empty means no new payload keys and the page is exactly as before. Tables (written by other jobs, never here): `competitor_ad_transcript`, `competitor_ad_tags`, `competitor_landing_pages`, `competitor_lp_media`, `competitor_ad_lp`.
- **Tags win over the text-only class.** When `competitor_ad_tags` has a cluster, pain point or new-angle flag for a library id, it replaces `competitor_concept_class` for that ad everywhere (angle chart, cards, spotlight, brand angles).
- **Tag filters** `?style= &hook= &device= &offer=` (case-insensitive exact match, kept in the URL with week / format / view) narrow every number, the spotlight, tile previews, galleries and charts on `/api/competitors` and `/api/competitors/<brand>`; untagged ads drop out while a filter is on; ignored when the tags table is absent. `tags.options` lists the values that exist for the week and format (not narrowed by the filters, so they can be changed); `tags.empty` drives the one 'No tags yet' line.
- **Lightbox** gets tag chips (Style, Hook type, Device, Proof, Emotion, Offer; the first four of those that are filters are links), 'Why it works', the hook quote, closed disclosures for what is on screen / what is said / transcript, and a 'Landing page' line that opens that page's lightbox.
- **'What competitors are doing'** (`learn`): per Style, Hook type, Device, Proof mechanism, Emotion, Offer type, the share of tagged competitor ads (denominator = tagged ads with a value for that dimension) next to Lonvera's share of Meta spend over the last 30 days to the last day in `family_daily`, one row per ad family (its first tracker row), blank tracker values left out, for the dimensions Lonvera has (Style, Proof Mechanism, Emotion from `tracker_rows`); the rest show competitors only. A value is highlighted when competitors lean on it at least 15 percentage points harder than Lonvera and at least 5 tagged ads carry it. The chart sentence is built from the numbers, not a model. 'Most copied this week' = top 5 hook type + device combinations with ad and brand counts and the longest-running example. Tags are model-read, so approximate.
- **Brand detail**: `tag_mix` (top three style, hook type, device with counts, chips that apply the filter).
- **Landing pages**: `landing_pages[]` on the brand detail become cards (screenshot at `lp_thumb_url` when a `competitor_lp_media` row exists, else the hero headline on a tinted block; page type, key theme, up to 5 selling points, offer / price / guarantee, proof and urgency chips, 'Changed this week' with the change note, ads pointing at it, link to the page) and open a lightbox with every field; with no LP rows for the brand the old `[{page, ads}]` counts stay. `lp_patterns` on `/api/competitors`: page types, proof elements, urgency devices, selling points (grouped by lowercase exact match), guarantee lengths parsed from text (days, weeks, months, years), counts are pages, plus the pages that changed (shown in 'What changed this week'). With a format or tag filter on and ads linked to pages (`competitor_ad_lp`), only pages some visible ad points to count. Ads carry `landing_page {lp_id, page_type, key_theme}` when mapped.

## Thumbnails (`competitor_ad_media`, migration 246)
Ad Library image links are signed and expire in days, so the bytes are stored. Per brand, right after its rows are written, the run downloads the creative image (video ads: the poster frame) of a curated slice: the 12 longest-running distinct concepts plus up to 8 distinct concepts that started within 7 days (ids already stored are skipped after the choice), at most 400 per run. Each is re-encoded to JPEG, at most 480 px wide and 150 KB (Pillow), 0.3 s between downloads, polite User-Agent, https on facebook / fbcdn hosts only, no login. A failed image is counted and logged (`stats.media`: selected, stored, failed, no_image, bytes, pruned) and never touches the brand's ad rows. Rows older than 60 days that are not in the latest week are pruned. `--no-media` skips all of it.
- `python -m etl.competitor_ads --media-backfill [--week YYYY-MM-DD] [--brand NAME]` fills thumbnails for ads already stored: no brand-page scrape, no `competitor_ads` writes, same selection over the latest (or given) week, one single-ad search per missing image (`?q=<Library ID>&search_type=keyword_unordered`, which returns exactly that card; `?id=` shows the advertiser's whole page instead), 1 s between ads, progress every 20, resumable (stored ids are skipped). Measured 2026-11-12: about 3 s per ad, 14 of 14 stored.
- `GET /api/competitors/media/<library_id>` (login required, digits only) returns the JPEG with `Cache-Control: private, max-age=86400`, or 404 `{"error": "not found"}`. Code: `app/competitors_media.py`.

## Playable videos (`competitor_ad_video`, migration 257)
Ad Library video links are signed and expire in about 4 days (the `oe=` hex timestamp in the URL, measured 2026-11-13: 4.4 days), so a playable copy is stored for the curated videos only: the same selection as the thumbnails (per brand the 12 longest-running distinct concepts plus up to 8 new this week), restricted to ads whose `format` is video, at most 400 per run.
- **Where the file comes from.** The public card already carries `<video src=https://video-*.xx.fbcdn.net/...mp4>`, so the weekly scrape reads it from the brand page (`vsrc` in `CARD_JS`, `video_url` on the parsed ad) and `--video-backfill` reads it from the single-ad page. Only Meta's SD rendition is offered (`sve_sd`, H.264 + AAC, 360 px wide, about 230 kbps video + 48 kbps audio, about 35 KB per second). A plain GET with the polite User-Agent and no Referer works (the CDN answers `Access-Control-Allow-Origin: *`, `Cross-Origin-Resource-Policy: cross-origin`, `Accept-Ranges: bytes`), https on facebook / fbcdn hosts only, no cookies, no login.
- **Why a copy, not a hotlink.** Hotlinking would technically work for about 4 days (no CORS or CORP block), but the link then dies and the signed URL is in no stored row. Our CSP (`default-src 'self'`) already covers `media-src 'self'`, so playing our own copy needs no header change. The Ad Library page itself cannot be framed (`X-Frame-Options` / `frame-ancestors`, the route is out).
- **Encoding.** `encode_video`: ffmpeg stream copy of the first 30 seconds with `-movflags +faststart` (moov first, so it streams and seeks), no re-encode and no quality loss, because the source is already smaller than any target we would pick. A source that is not H.264 / AAC is re-encoded (H.264 main + AAC, at most 480 px wide, 650 kbps video, 64 kbps audio); a result over the **6 MB per-video cap** is re-encoded once at 300 / 48 kbps; still over: skipped, reason counted in `stats.video.skipped`. If ffmpeg is not on the machine the original is stored as is when it is an mp4 and fits the cap, otherwise skipped ("no ffmpeg and original over the size cap"). ffmpeg (Debian package, with ffprobe) is installed in the jobs flavor of the Dockerfile only; the web image never runs it.
- **Size control.** `--max-video-mb` (default 300) caps the whole table: at the cap capture first evicts videos of ads that are not in the latest week (oldest first) and otherwise stops (`stats.video.capped`); the end of every run also trims to the cap, shortest-running latest-week ads first, so the longest-running ads of the latest week are the last to go. Rows older than 21 days whose ad is not in the latest week are pruned. Per-ad failures are non-fatal and logged; `competitor_ads` rows are never touched. `--no-video` skips video (thumbnails still run); `--no-media` skips both.
- `python -m etl.competitor_ads --video-backfill [--week YYYY-MM-DD] [--brand NAME] [--max-video-mb N]`: videos for ads already stored, no brand-page scrape, one single-ad page per missing video, 1 s between pages, 0.5 s between downloads, resumable (stored ids skipped).
- `GET /api/competitors/video/<library_id>` (login required, digits only, read only) returns the mp4 with `Accept-Ranges: bytes`; a `Range` header gets `206` with `Content-Range` and the slice (open-ended and suffix ranges too), an unsatisfiable one `416` with `Content-Range: bytes */<size>`; `Cache-Control: private, max-age=86400`; absent or non-digit id: 404 `{"error": "not found"}`. Code: `app/competitors_media.py`.
- **Lightbox.** A video ad with `video_url` shows a `<video controls playsinline preload="metadata" poster=thumb_url>` plus a Play button over the poster (sound on, no autoplay). Previous / next, the arrow keys, swipe (not on the controls bar) and close all pause it. Gallery and rail cards of ads with a saved video carry a play badge. A video ad without a saved copy keeps the still and the line "Video not saved. Open in the Ad Library to watch." next to the Ad Library link.
- Storage (measured 2026-11-13 on 40 real ads from five brands, trimmed to 30 s): mean 1.16 MB per video, median 1.11 MB, max 2.8 MB; untrimmed originals averaged 2.1 MB (max 9.4 MB, 1 of 40 over 6 MB). About 70 curated videos is about 80 MB. Videos do not compress in `pg_dump`, so every stored MB adds one MB to each nightly dump Projection (estimate, one week of data): about 70 videos is about 80 MB; weekly additions of 15 to 30 new videos are about 20 to 35 MB; with the 21-day prune the table settles near 150 to 200 MB, under the 300 MB cap. (see docs/BACKUP.md: dump 470 MB for a 716 MB database on 2026-11-09, the backup container needs about 2x the dump plus the restored database in free disk).

## Landing pages (`competitor_landing_pages`, `competitor_lp_media`, `competitor_ad_lp`, migration 262)
`python -m etl.competitor_landing_pages` (run by hand for now; NOT scheduled in the nightly etl until Josh approves; `--if-sunday` exists for when it is) opens every distinct landing page the week's competitor ads point to, keeps a small screenshot and tags the page, so we can learn from the pages and not only the ads.
- **Which pages.** `competitor_ads.landing_url` of the latest stored week (or `--week`). Each is normalised to `url_key` = lowercase host without `www` + path without trailing slash; `utm_*`, `fbclid`, `gclid` and every other query parameter are dropped, only page-selecting ones (`variant`, `variation`, `version`, `v`, `offer`, `pid`, `product`, `sku`, `p`, `lp`, `page_id`, `id`, `plan`) are kept. `lp_id = sha1(url_key)[:16]`, so the same page across ads and weeks is one `lp_id`. Not opened: no landing URL, non-http, social hosts (facebook, instagram, youtube, tiktok ...). At most 200 distinct pages per run, the most-used first (`--limit` lowers it); the page's brand is the brand with the most ads on it. `landing_url` is mostly the display domain and path from the Ad Library card (no query string; `landing_from` keeps host + path only), so the page opened is that URL with `https://` in front and redirects followed; `final_url` is where it ended.
- **Capture.** Headless Chromium (Playwright), User-Agent `LonveraCompetitorResearch/1.0 (...)`, viewport 1280x900, 3 s between pages, 20 s timeout, an obvious cookie Accept / Close clicked and nothing else, scroll down in steps for lazy content, then visible text (title, h1 / h2 / h3, bullets, price / guarantee / review / urgency strings, FAQ questions, buttons, the top of the body, about 12 KB) and the above-the-fold screenshot (JPEG, at most 640 px wide and 90 KB, quality lowered once if needed). No login, no captcha solving, no bypass: a 401 / 403 / 429 / 503 status, a challenge page or a blank page is recorded in `http_status` / `fetch_error` and skipped (tags stay NULL, no screenshot). A failure on one page never touches the others. `--no-tag` captures only.
- **Tags** (headless Claude exactly like `etl.auto_tag`: `claude -p`, Sonnet, Read only, batches of 5, screenshot + text, JSON validated, one retry for the answers that failed; instructions in `etl/competitor_landing_pages_instructions.md`): `page_type`, `key_theme`, `hero_headline` (quoted), `selling_points`, `offer_summary`, `price_text`, `guarantee`, `proof_elements`, `urgency_devices`, `objections`, `cta`, `why_it_works`, and the Lonvera `cluster` / `icp` / `pain_point` from the same catalog `etl.competitor_ads` classifies against (a NEW angle may carry its own label). Quote, never invent; unknown = NULL; no em dashes in generated text.
- **Week over week.** `content_hash` = sha1 of the normalised key lines (title, headings, bullets, prices, guarantee, reviews, FAQ, buttons) with clocks and counters removed (a ticking timer or "17 left" is not a change; page body text is not hashed so rotating testimonials are not either). `changed_from_prior` compares it with the latest earlier week of the same `lp_id` (false for a first sighting); for changed pages with a tagged earlier week one extra call writes `change_note` from the old vs new tag lines. A changed hash can still be an A/B variant served on that visit.
- **Resumable.** A page tagged this week is skipped; a page that answered with a wall / 4xx is not retried (use `--retag`); a timeout / DNS failure is retried; a `--no-tag` page is re-opened by the next tagging run because the text is not stored. `competitor_ad_lp` (week, library_id -> lp_id) is rewritten for every ad that maps. Screenshots older than 60 days that are not the latest week are deleted; page rows are kept as history.
- **API.** `GET /api/competitors/lp-media/<lp_id>?week=YYYY-MM-DD` (login required; `lp_id` is 16 hex characters, else 404; `week` defaults to the latest stored for that lp_id) returns the JPEG with `Cache-Control: private, max-age=86400`, or 404 `{"error": "not found"}`. Code: `app/competitors_media.py`. The /api no-store header exempts this path like `/media/` and `/video/`.
- Usage: `python -m etl.competitor_landing_pages [--week YYYY-MM-DD] [--brand NAME] [--limit N] [--retag] [--no-tag] [--dry-run] [--if-sunday]`. `--dry-run` only plans (counts distinct pages, no browser, no claude, no writes).

## Chatter sources (`python -m etl.competitor_chatter`, table `competitor_posts`, migration 244)
Non-Meta signal: what people and the press say about watched brands and the category. Tested 2026-11-12 from a Mac (residential IP), logged out, descriptive User-Agent, no paid scrapers, no captcha or bot-detection bypass.

| Source | Works | Evidence / limit |
|---|---|---|
| Google News RSS (`news.google.com/rss/search?q="Brand" when:14d`) | yes | 200, 1-15 items per brand query (Heart & Soil 15, Nutrafol 9, Primal Queen 4, My Marrow 2); category phrases return 0-3. 1.5 s between queries. Datacenter IPs generally fine. Google's feed terms say personal / non-commercial use: internal competitor monitoring, headlines only, no republishing. |
| Reddit subreddit RSS (`www.reddit.com/r/<sub>/new/.rss?limit=100`) | yes, slowly | 200 with 100 entries (r/Supplements, r/carnivore). Budget is about one request per minute per IP (`x-ratelimit-remaining: 0` after one call, reset about 45 s; extra calls get 429). We wait 65 s between subreddits and stop the source on the first 403 / 429. The RSS carries no score or comment count. Reddit has historically blocked datacenter IPs: UNVERIFIED from Railway, the run records the failure and still completes. |
| Reddit search (`search.json`, `search.rss`, subreddit `search.rss`) | no | 403 (blocked for logged-out clients); `old.reddit.com` search RSS redirected (302); a later probe of `old.reddit.com/r/carnivore/new/.rss` returned 200 with a rate-limit budget of 199 but an HTML body, not Atom (0 entries, probably a login / consent page, not inspected): not usable as tested. |
| Reddit `.json` endpoints (`new.json`) | no | 403 with a block page. |
| Trustpilot public review pages | no | 403 "Verifying Connection" bot wall; not attempted further. |
| Hacker News (Algolia API) | works but useless | 200, but zero relevant hits for brand / category terms (tech audience). Not built. |

Not used: any paid API, login, OAuth, proxy or captcha solving. Rate limits respected: 1.5 s between Google News queries, 65 s between Reddit requests (about 8 subreddits = about 9 minutes), hard cap 400 rows per run.

Flow: brands = active rows of `competitor_brands` (first non-domain search phrase, exact-phrase query) plus the `CATEGORY_TERMS` constant; Reddit reads `SUBREDDITS` newest posts and keeps those that mention a brand phrase or category term; spam regex drops junk; only the last `--days` (14) are kept; upsert on `(source, url)`; `week_start` = Monday (Pacific) of `posted_at`; one failing query or source is logged (scrubbed) and skipped. The job fails (etl_runs) only when every source returned nothing and something failed.

## Ad tags and transcripts (`python -m etl.competitor_tags`, tables `competitor_ad_tags` and `competitor_ad_transcript`, migration 261)
For the curated ads that have a saved picture or video (the slice in `competitor_ad_media` / `competitor_ad_video`) the ad is tagged by LOOKING at it, with Lonvera's tags and with learning tags, so competitor ads compare 1:1 with ours and show what they do well.
- **Transcripts.** Saved videos are transcribed with faster-whisper (model `base`, int8, CPU, VAD filter; audio decoded by ffmpeg to 16 kHz mono, because PyAV 19 breaks faster-whisper 1.2.1's own decoder) into `competitor_ad_transcript` (`transcript` is '' for a video with no speech). faster-whisper is an OPTIONAL extra (`requirements-whisper.txt`, pins `huggingface_hub<1.0`); without it the run notes `transcribe_skipped` and tags with method `vision`. Measured 2026-11-13 on a Mac: 1.4 to 2.7 s per 30 s video after the model is loaded.
- **Tagging.** Batches of 6 ads per `claude -p` call (same helper as `etl.auto_tag`: Sonnet, Read tool only, cwd = a temp dir holding the pictures; verified 2026-11-13 that headless Claude opens local jpgs there and quotes what is on them). Each ad gets its stored JPEG (image ads and video posters) plus 4 ffmpeg frames for videos, the transcript, copy, brand and days running. Instructions: `etl/competitor_tags_instructions.md`.
- **Which tags.** Lonvera taxonomy from `taxonomy_lines` (line, cluster, ICP, pain point, emotional trigger; or `NEW` with a label, or `OUT`; falls back to the shipped catalogs on an empty table); style, fidelity, proof mechanism and emotion from the distinct non-deleted Creative Tracker values (same lists as the launch draft), where `PROPOSE: <value>` is stored as is and shows which values the tracker lacks; learning tags hook type, offer type, device (closed lists in code), call to action (<= 8 words), hook text (<= 20 words, quoted), why it works (one sentence, <= 25 words) and `seen_on` / `said_on` (the evidence). No em dashes (replaced).
- **Method.** `vision_transcript` = picture and speech, `vision` = picture only (no speech, or no whisper), `text` = no picture could be read (confidence capped at medium).
- **Validation.** Every answer is checked against the allowed values; ads that fail (or are missing from the answer) are asked again once, alone; still failing: skipped, the reason counted in `stats.skipped`, nothing invalid stored. Auth failure / usage limit stops the run (job `competitor_tags` failed in etl_runs). A transcription or frame problem on one ad never stops the batch.
- **Resumable.** Ads already tagged at `TAG_VERSION` are skipped; bump the constant after changing the instructions or lists. `--retag` replaces rows (an ad that fails again keeps its old row). Default week = the latest week with saved media. `--limit` (default 80) caps ads tagged per run.
- **Cost measured 2026-11-13** (6 ads, 2 videos): about 5 s and about $0.02 of notional plan usage per ad (one call per 6 ads: about 4 output tokens in the low thousands, about 22k tokens cache-created for the instructions plus the 157-line taxonomy table).
- **Not wired into `scripts/deploy/run_etl.sh`.** The jobs image would need faster-whisper + onnxruntime + PyAV + numpy (about 170 MB of wheels) and the `base` model (141 MB, downloaded on first use into an ephemeral container cache, so every nightly run would download it again unless a volume is added). Run by hand after `etl.competitor_ads`: `python -m etl.competitor_tags --limit 80` (add `--no-transcribe` for a run that needs no extras). Without whisper the same call is cheap enough to schedule later (Claude only).
