# Questions and assumptions (drivers)

Each default is already built; change the line named.

1. **Revenue stack timing.** Repeat, DTC, sales tax and total company revenue need the cohorts' repeat revenue, which runs after drivers. Default: `revenue_lines(drivers, repeat_rev, dtc_actual)` in `app/projection/drivers/revenue.py`, called by the pnl module and the page, with `reconcile_map.py` rows 18, 21, 22 resolving through `pnl.lines.*`. If the foundation wants rows 18-22 reconciled without pnl, a generic engine hook would do it: after all modules run, call `result.finalize(results)` on any result that defines it (about five lines in `engine.py`); drivers would then attach the stack itself. Not applied (file not mine).
2. **Lock closed months per cell.** `grid.js` has no per-cell or per-row "editable only in projected months", so plan rows are amber in closed months and an edit is refused by the page's `onEdit` with a plain message. Suggest a row option (for example `row.lock = 'actual'`) that renders actual-month cells as calculated and not editable.
3. **Grid vocabulary.** Same as `QUESTIONS_cohorts.md` item 1: `Table` / `Row` accept `line|memo` and `money|int|...`, the shell reads `calc|input|ratio` and `usd|usd0|num`. The drivers payload is built as plain dicts in the shell's vocabulary.
4. **Clones are detached now** (core lifecycle change), so clearing a cell in a copy removes it. The NC-ROAS slide stays a lever that governs a month range (a typed CPA inside the range counts only as an override) rather than a deletion of typed cells, so turning the slide off brings the typed CPA back.
5. **Today.** `engine.run(today=...)` is not passed to modules. The drivers module reads the business date from `loaders.current_date()` (Pacific, via `freshness.today_pacific`); tests patch that function. Suggest passing `today` through `load_inputs` for all modules.
6. **Seed and restore baseline** (answers `QUESTIONS_financing.md` item 3). `etl.projection_drivers seed` writes the plan and levers directly, then captures them with `scenarios.lock_for_change`, so on a fresh scenario the seeded plan is version 1 and History cannot restore to an empty plan; on a scenario that already has history the seed is its own version (`finish_change`).
7. **Which feed wins.** Books (`pnl.mkt_*`, then the seeded `spend.*`) beat the Meta feed (`spend.meta_feed`), month by month; a feed-only month estimates the other channels from the channel mix lever. Change the order in `loaders.py` if Josh wants the feed to win.
8. **Decisions for Josh** (from the reconcile): the July 2026 ad spend ($794,965 typed vs $888,015 in QuickBooks), and whether to clear the Aug-Oct 2026 typed new-customer overrides so the cohort table drives them.
9. **validate_series hook and expected_version.** Resolved: the core calls `MODULE.validate_series(conn, scenario, items)` on every `apply_items` path. `lib/api.js` adds `expected_version` automatically only for `PUT /series`; the Spend plan page sends it itself on `PUT /drivers/series`, patterns and levers. Adding `/<module>/series` to `versionedSlug` would give the conflict dialog for free.
10. **Month status words.** Agreed with proj-pnl: `books` / `feeds` / `projected`; `DriversResult.actual_through` is now `books_through` (was the last month with any loaded spend), `feeds_through` is the last month with books or feed data. The core's `/run` should expose `month_status`.
11. **Clock.** `loaders.current_date()` imports `today_pt` from `app/projection/clock.py` when it exists, else `freshness.today_pacific`.
