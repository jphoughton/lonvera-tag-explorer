# Variables registry

What this is: every input that drives the Lonvera Projections model, as a named, scenario-aware variable with the sheet's value as its default, the sheet cell it came from, and how the engine uses it. The page `/projection/variables` lists and edits them; `app/projection/variables/specs_<module>.py` is the single source and this file is generated from it (`python tests/projection/variables/tools/render_registry.py`; a test fails when the two differ).

## TLDR

- 315 variables: 288 implemented (a test moves each one and an engine output changes), 5 partly wired, 22 sheet items the model does not carry.
- 258 are single numbers or switches, edited in place on the page; 14 are monthly series (271 typed months in the sheet) and 21 are tables (orders, cohorts, rows), edited on their module page with a summary and a link here.
- Gaps still open are in `docs/projection/TICKETS_<module>.md`: one cost line whose driver cannot be saved, feed rules fixed in code, the TikTok ads formula, and intraday inputs the pacing module does not take. Closed during the build: one store for the payback inputs (`drivers.payback.*`), one store for the China landed cost (`pnl.cogs.china_cost.<sku>`), and typed demand rates above 1.

Status meaning: **IMPLEMENTED** the engine reads it and a test (`tests/projection/variables/test_variables_access.py`) moves it and sees an engine output change (or the planner's proposal for planner rules); **PARTIAL** it is exposed but stored twice, only changes what a page shows, or has no edit path yet; **MISSING** the sheet has it (a yellow cell or a number inside a formula) and the app does not, with the reason.

## How the sheet was audited

1. **Typed inputs.** The live sheet's cell fills were read read-only (`tools/fetch_sheet_fills.py`, yellow = Josh's input convention) and joined to the frozen snapshot (`tools/yellow_inventory.py` -> `fixtures/yellow_cells.json`). Plus every typed number in a forward month of a formula row, every column B driver on the P&L, and the levers on Payback, Term Debt, Curves, Fixed Expenses, Vendor COGS, COGS, the three Fcst Inputs tabs, Purchase Orders, Automated Pacing and the payout block.
2. **Literals inside formulas.** `tools/formula_literals.py` parses every formula of the 40 model tabs, drops strings, references, function names, dates, and 0 / 1 / 2 / 12 / 100, groups formulas that differ only in references, and lists what remains (33 patterns). Each is classified below.
3. **Selectors.** Dropdown and switch cells, below.
4. **Code.** `tools/code_literals.py` lists numeric constants in the seven module packages; each is a lever default, a validation bound, or a gap (`TICKETS_<module>.md`).

## Registry

Columns: id; variable; kind (value, series, table); unit; the sheet's value; sheet reference; status; how the engine uses it; notes and ticket. A value in brackets after the status means a scope: `all` = shared by every scenario, `feed` = a loader rule applied when data loads.
