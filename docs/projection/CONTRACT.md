## Security (binding, revised 2026-11-03: Josh chose NO password for projection)
Projection has no login of its own. It follows the app's auth setting exactly: when the Tag Explorer runs with `AUTH_DISABLED=1` (the public URL), projection is open; when the app has its login on, the app's existing `/api/*` guard covers `/api/projection/*` with no projection code. Do NOT add a password, a login screen, a session endpoint, a `PROJECTION_PASSWORD`, or any fail-closed-on-missing-secret behavior. Because the data is sensitive and writable, add these password-free guard rails instead:
- **Audit + undo.** Every mutation writes `proj_audit` (old and new values). Every scenario version bump snapshots the scenario (params + all its series as jsonb) into `proj_scenario_history(scenario_id, version, snapshot jsonb, at, action)`, keep the last 200 per scenario. `POST /api/projection/scenarios/<slug>/restore {version}` restores (itself audited and versioned). `GET /api/projection/audit`.
- **Hard to wreck.** `current` cannot be deleted; deleting any scenario requires `{confirm:"<slug>"}` in the body; bulk series PUT <= 500 items; uploads are preview-then-commit (`?commit=1`), size-capped, closed months only, never overwrite a month without showing the diff.
- **Abuse limits.** In-memory per-IP rate limit on mutations (default 120/min) and on uploads (default 20/hour), 429 `{error:"rate_limited"}`; JSON content type only; Origin must match when present (blocks cross-site browser writes); request cap 1 MB (uploads 8 MB).
- **Not indexed.** `X-Robots-Tag: noindex, nofollow` on `/projection*` pages and `/api/projection/*` responses, and `Disallow: /projection` + `/api/projection` in `/robots.txt` (add the route if the app has none, in the projection registration, without touching existing routes).
- **No secrets, no customer-level data** in projection tables (aggregates only: cohort rollups, monthly lines, PO rows). Env var names only in code and docs.
- Tests: projection endpoints work without a cookie when the app's auth is disabled; return 401 when the app's auth is on; audit row per write; restore round-trip; `current` undeletable; delete without confirm 400; rate limit 429; robots header present; a module endpoint added later is covered with no code in the module.

## Time axis
60 months, `2025-01-01 … 2029-12-01`, index 0..59, `date` first-of-month. A month is **actual** if `proj_actuals` has loaded data for it and it is closed (before the first day of the current month); everything else is **projected** (asterisk in the UI). The sheet's hard-coded Jul-26 cutoff is not reproduced.

## Interchange (dataclasses live in `app/projection/interfaces.py`, written by foundation exactly to this)
```python
Month = date  # first of month
Series = dict[Month, float]            # sparse allowed; engine reads missing as 0 unless stated
@dataclass class Scenario: id:int; slug:str; name:str; params:dict   # params[<module>] namespaces; series via series.get(scn, key, month)
@dataclass class DriverResult:         # module drivers
    spend_total, spend_meta, spend_google, spend_amazon_ads, spend_tiktok, nc_cpa, nc_aov, nc_orders, nc_rev, nc_roas, amazon_rev, tiktok_rev, sales_tax: Series
    actual_through: Month               # last month with actual data
@dataclass class CohortResult:          # module cohorts
    curve_live: list[float]; curve_goal: list[float]   # ages 1..60
    lifetime_multiple: float; repeat_rev: Series       # modeled repeat $ per month, all cohorts incl. forward
    repeat_rev_actual: Series; cohort_rows: list[dict]
@dataclass class PnlResult:             # module pnl
    lines: dict[str, Series]            # keys = LINE_KEYS in app/projection/pnl/lines.py (stable snake_case, one per sheet row)
    fy: dict[int, dict[str, float]]; ttm: Series; ftm: Series; ev: dict
@dataclass class DemandResult: units: dict[tuple[str,str], Series]   # (location, product) -> units per month; locations revamp|amazon|intl
@dataclass class InventoryResult: outlay: Series; value: Series; burn: dict; reorder: list[dict]   # inventory_supply; outlay = cash by month
@dataclass class FinancingResult: lines: dict[str, Series]   # interest, principal, balance, tax, equity, cash_after_inventory, ending_cash
```
Each module package exports `MODULE = Module(key, load_inputs(conn)->Inputs, compute(...), blueprint, ui='<module>.js')` in `app/projection/<module>/__init__.py`; `registry.py` auto-discovers them (missing module = "not built yet" card in the shell). Orchestration order in `engine.py`:

1. `drivers.compute` → `DriverResult` (actual months from `proj_actuals` + cohort first-order revenue; projected months from scenario series/levers).
2. `cohorts.compute(nc_rev=drivers.nc_rev)` → `CohortResult` (forward cohorts' first-order revenue is the drivers' NC revenue).
3. `pnl.compute(drivers, cohorts)` → `PnlResult`.
4. `inventory_demand.compute` → `DemandResult`; `inventory_supply.compute(demand)` → `InventoryResult`.
5. `financing.compute(pnl, inventory)` → `FinancingResult`.
6. `pacing` reads actual feeds + `pnl` targets; no downstream consumers.

Until a module upstream is built, `engine.py` uses a **fixture stub** (values from the snapshot) so every agent can develop and test its own module alone. Write tests against both the stub and, once present, the real upstream.

## Data conventions
- Tables prefixed `proj_`. Money `numeric(18,2)`, rates `numeric(10,6)`, months `date` (first of month), units `numeric(18,2)`.
- Scenario-independent facts (actuals, cohort table, POs, vendor costs, snapshots) have no `scenario_id`. Anything a scenario can change is a **lever** (scalar in `proj_scenarios.params`) or a **monthly series** (`proj_series(scenario_id, line_key, month, value, kind('input'|'override'), note)`). Seed "Current plan" (slug `current`) from the sheet's typed cells; scenarios clone with `POST /api/projection/scenarios/<slug>/clone`.
- Every write goes through `app/projection/rwdb.py` (read-write pool, separate from the app's read-only pool) and is audited in `proj_audit`. Writes follow the Security section and JSON bodies <= 1 MB (uploads: multipart <= 8 MB, endpoint-specific).
- API: `/api/projection/...`, JSON, Decimals as floats, no secrets, same error shape as the app (`{error}`). A module's blueprint prefix is `/api/projection/<module-with-dashes>`. A computed table endpoint returns `{months:[iso…], status:['actual'|'projected'…], rows:[{key,label,kind,fmt,values:[…],input:bool}], captions:[…]}` so the shared grid renders it; `input:true` rows are editable cells (PUT `/api/projection/series`).
- Never hard-code a value the sheet computes: dynamic formulas, not typed values. Typed values are only inputs (levers/series/actuals) and each carries its source in `note`.
- UI rules (Josh's standing sheet rules apply to every page): months as columns, entities as rows; currency with thousands separators; status colors; one very short source caption per table; asterisk on projected values; labels read as a finished document (no build history, no design rationale); status chips for OUT/OVERDUE etc. Use only the vendored `chart.umd.min.js` and ES modules (no CDN, no build step). Wide tables scroll horizontally on mobile.
- No compliance hedging, no banned-word lists in any copy. No secrets in code or docs: env var names only.
- Python style: match `app/api.py` / `app/queries.py` (typing, small functions, parameterized SQL only, no string-built SQL, `psycopg` 3).

## Done for a module
1. Engine reproduces the sheet's values for its rows from the sheet's own typed inputs, month by month, within **0.5% per cell** (or $1), on the frozen snapshot; every difference above tolerance is listed with its cause in `MODULE_<module>.md` (sheet bug, stale hard-code, intended change). Run `scripts/projection/reconcile.py --module <key>`.
2. Unit tests (`tests/projection/<module>/`, pytest, own DB) cover the engine, loaders, API (auth required, validation, audit row on every write) and edge cases (empty months, zero denominators, month boundaries).
3. Page renders against local data; loaded in a real browser and screenshotted (Browser pane via `preview_start` with a `.claude/launch.json` entry named `projection-<module>`, or Playwright from `~/lonvera-tag-explorer/.venv`). Console clean.
4. Report: what was built, files, tests (counts), reconciliation table (max abs/relative diff per line), open items. Verified, not "should work".
