# Questions and assumptions (cohorts)

Each default below is one line to change.

1. **Grid vocabulary.** `app/projection/interfaces.py` (`Row`/`Table`) accepts row kinds `line|subtotal|total|header|memo` and formats `money|money2|int|num2|pct|pct1|x|text|date`, while the shell grid (`lib/grid.js`, `lib/format.js`) reads `calc|input|subtotal|total|header|ratio` and `usd|usd0|pct|num|x|text|date`; a `memo` or `money` row is not styled by the shell. The cohorts payloads are built as plain dicts in the shell's vocabulary (`views.py`, `_row`), as the drivers and pnl modules do. Suggest foundation either maps one set to the other in `Table.to_payload` or replaces `KINDS`/`FMTS`; then `views.py` can move to `Table`.
2. **Non-strict engine in the API.** The cohorts endpoints call `engine.run(...)` without `strict`, so a failing or half-built module (missing tables) falls back to its stub and this page still loads; only a failure of the cohorts module itself is a 500. `reconcile.py` runs strict, so it needs every module's tables present (applied here with all migrations to the cohorts database only).
3. **Date seam.** Month-closed rules use today in Pacific time (`app.projection.freshness.today_pacific`), through one function, `app.projection.cohorts.model.today()`. The engine's own `today=` argument is passed for the stubs only.
4. **Default `n_cohorts` = 3.** The snapshot says "Last 3 Cohorts Avg"; `context/ma-calano.md` says 6 from 2026-11-03. Reconciled against the snapshot, so 3 (a lever). Josh to confirm.
5. **Per-customer precision.** `numeric(18,6)` for per-customer dollars and `numeric(12,6)` for payback instead of the money default `(18,2)`, so the curve and a re-upload diff are not distorted by rounding.
6. **`curve_live` vs the curve in use.** `CohortResult.curve_live` is always Live (the drivers module's payback reads it); the curve applied to repeat revenue is the extra attribute `curve_used`. If a scenario selects Goal, the drivers payback still uses Live; say if it should follow `curve_used`.
7. **Curve choice (P&L card).** New levers `curve_source` (live, goal, asof, blend) and `asof_month`; the earlier `curve` lever is read as `curve_source`. "As of Aug 2026" means data through the end of August (Aug closed); a snapshot taken while August was still open is the Jul 2026 entry. A month is offered when ages 1 to 12 each have at least the chosen number of cohorts (3 or 6) behind them.
8. **Edits outside the cohorts files.** `app/static/js/projection/pnl.js`: one import, and two lines plus the `replaceChildren` list entry that mounts the card. `app/projection/variables/specs_cohorts.py`: `curve` renamed `curve_source`, `asof_month` added (the Variables page lists it); `docs/projection/VARIABLES.md` regenerated with `tests/projection/variables/tools/render_registry.py`; `tests/projection/variables/test_variables_page.py`: the cohorts row count 8 to 9.
9. **Scenario inheritance.** A scenario that never saved a curve choice shows its base scenario's choice (the core's clone-with-link rule), so changing the plan of record's curve changes every copy that never chose its own. Saving from the card writes the choice explicitly, which isolates that scenario from then on.
10. **Existing failures not caused by this change.** `tests/projection/pnl/test_pnl_page.py::test_changing_a_driver_updates_the_projection_and_the_row` and two variables page tests (`test_editing_a_number_saves_flags_it_and_reset_goes_back`, `test_a_bad_value_shows_the_reason_and_keeps_the_old_one`) fail with the picker unmounted too: they edit the plan of record and meet the new plan-of-record prompt. The picker's `/curve-options` answers `available: false` (200) when the cohort tables are missing, so a database without them (the pnl suite's) shows no card and no console error.
11. **Upload checks classification.** Customer count against neighbours blocks only when it revises a stored cohort (3,614 to 12) and is a warning for a new cohort: the real table grows from 62 to 15,000 customers a month, and Dec-25 sits 61% above its neighbours, so blocking a new cohort on that rule would refuse real data. First order against neighbours skips cohorts under 1,000 customers (Feb-Jun 2024). Both can be widened on the Variables page. Dips: under 0.5% ignored, up to 5% a warning, above 5% blocks. proj-core validator hooks: none were available, the checks live in `app/projection/cohorts/checks.py` and can move behind a hook later.
12. **Variables page.** The eight upload bands are registered (probe none: only the upload preview reads them), so the cohorts section of the Variables page test is 17 rows (was 8); `docs/projection/VARIABLES.md` regenerated. `tests/projection/variables/test_variables_access.py::test_moving_a_variable_moves_an_engine_output[pacing.cpa_window_days]` started failing during this work; it does not touch cohorts.
