# Module brief: inventory_supply (P2) — migration 150, `app/projection/inventory_supply/`, page `inventory_supply.js`

Replaces `Purchase Orders`, `Vendor COGS`, `FBA Transfers`, `Warehance Inventory Burn`, `Intl Inventory Burn`, `Amazon Inventory Burn`, `Total Inventory Burn`, `Warehance Reorder`, `Intl Reorder`, `Inventory Value`, `Inventory Cash Outlay`. Input: `DemandResult` (inventory_demand module; until it lands use the contract stub). Output `InventoryResult` (`outlay` cash by month feeds financing / P&L row 125; value; burn; reorder).

## What the sheet does (read formulas in the snapshot; ma-calano.md has the history incl. the 2026-10-04 and 2026-10-13 rebalances)
- `Purchase Orders` (rows 2–86+): Josh's PO entries and auto-plan rows: product, units, vendor (China → International 3PL, KeyStone → Revamp Utah), warehouse (col L; blank = Revamp Utah), land date (G), status (landed POs are already in on-hand: excluded from inbound), deposit % (M) → down payment (J), PO value = units × `Vendor COGS` unit cost (col H lookup), order date (D) = land date − vendor lead time (China 8 weeks, KeyStone 12). `Vendor COGS`: unit cost by vendor × product (China VB 2.26, BL 4.16, BF 2.55; KeyStone VB 3.92, BF 2.50, BL 5.00) + lead times.
- `FBA Transfers`: units leave Revamp in the ship month and land at FBA in the receive month (ship = receive − 1).
- Burn tabs (36 months from the rolling start month): opening → demand → inbound (POs by land month for that warehouse excluding landed/cancelled-handling per the sheet; transfers for FBA) → closing, months of cover, OUT flag, "units to send" row for FBA (target cover 1.5 months). `Total Inventory Burn` check row is nonzero in months where a transfer ships and lands in different months (in-transit units: diagnostic, not a bug).
- Reorder tabs: per-SKU lead time / safety stock (14 days) / MOQ; stockout date interpolated in the first negative month; must-land; order-by; status OVERDUE / ORDER SOON / OK; suggested PO = max(MOQ, 3 months of average demand).
- `Inventory Value` = units × China landed cost at month close (`COGS` tab unit costs; Vital Flow has $0 cost). `Inventory Cash Outlay`: deposits by order month + balances (PO value landing − deposits already paid) by land month = total inventory cash outlay; cumulative; international split.
- Known data flags (carry them as warnings, do not hide): duplicate 5,000 Vital Bull rows (PO rows 2 vs 6), PO rows 19–21 planned with Sep-6 order dates, FBA rows 4–6 receive-before-ship, "cancelled" status counted as inbound/cash in the sheet.

## Build
1. Tables: `proj_po`(id, product, units, vendor, warehouse, land_date, order_date, status, deposit_pct, unit_cost override, note, source('josh'|'auto-plan'), …), `proj_vendor_cogs`, `proj_vendor_lead`, `proj_fba_transfer`, seeded from the snapshot (`etl/projection_inventory_supply.py`, idempotent; PO ids stable by sheet row).
2. Engine: burn per warehouse × product; reorder status; value; cash outlay (deposit timing + balance timing); the PO auto-planner (3 months of forward demand whenever closing stock would fall below 14 days of safety, rounded up to 1,000; FBA transfers keep ≥1.5 months cover) as an explicit "Suggest plan" action that PROPOSES rows (never writes without an explicit accept), reproducing the planner rules in ma-calano.md.
3. API `/api/projection/inventory-supply/…`: `burn?location=`, `reorder`, `po` (CRUD with audit, validation: land date ≥ order date, status enum, units > 0), `transfers` CRUD, `value`, `outlay` (grid), `plan/suggest` (+`plan/accept`), `warnings`.
4. Page: PO table (editable, status chips: landed/in transit/planned/cancelled), burn grids per warehouse with OUT/low-cover chips, reorder list sorted by urgency, FBA transfers, inventory value and cash outlay charts, suggested plan diff view.
5. Reconcile map: each burn tab's closing and cover rows, `Inventory Cash Outlay` rows 5–11, `Inventory Value`, reorder dates; PO value/down payment/order date columns. Months align on the header dates; the sheet's start month rolls with TODAY(), so reconcile at the snapshot date.
