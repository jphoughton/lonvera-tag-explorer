# Questions and assumptions (ui shell)

Checked against `app/projection/api.py` / `scenarios.py` / `series.py` / `engine.py` as they stood on 2026-11-03. Each default is one line to change in `app/static/js/projection/lib/scenario.js`, `lib/api.js` or `shell.js`.

1. **Clone spelling.** The agent brief says `POST /api/projection/scenarios {name, clone_from?}`; the contract (data conventions) says `POST /api/projection/scenarios/<slug>/clone`. The backend implements both. The UI calls the first and, on 404 / 405, retries the second. "New" sends `{name}` without `clone_from` (the backend then makes a scenario from the default).
2. **History drawer inputs.** Resolved with proj-core: `GET /audit` rows now carry `version` (the version the change produced). The drawer lists the versions from `GET /scenarios/<slug>/history` and attaches audit rows by `version`; rows without a `version` fall back to the version written at the same time (2 s), anything else shows under "Other activity".
3. **Restore semantics.** The snapshot at version N is the state after change N (`finish_change` writes it after the bump), and the UI labels it "how it was at version N". Matches.
4. **`GET /run` headline.** Real shape `{fy:{'2027':{revenue,noi}}, ev:{...}, lifetime_multiple, lowest_ending_cash:{month,value}}`. The strip shows the year after `actual_through` (FY27 now). The `ev` keys are not known yet: numeric values under keys like `3x` / `8` show as an "Implied EV a to b" range; anything else under `ev` is ignored. Tell me the real `ev` keys when the pnl module lands.
5. **Series PUT.** Items are `{line_key, month, value|null, kind?='input', note?}`; `note` is only sent when the caller sets it. Duplicate cells in one request are merged client-side (the server 400s on them). `expected_version` is not sent, so concurrent edits from two tabs both apply (last write wins per cell). Say if the UI should send it and ask the user to reload on a 409.
6. **Text and date input rows.** `PUT /series` accepts numbers or null only, so an input row with `fmt:'text'` or `'date'` cannot be saved through the shared grid path; such rows need their own endpoint (the grid parses and displays them, the module's `onEdit` decides where they go).
7. **Delete.** Body `{confirm:"<slug>"}`, shown only for non-default scenarios. The backend answers `{deleted:slug}` with 200.
8. **Module URLs** use the dashed form (`/projection/inventory-demand`); the underscore key resolves too.
9. **FY columns.** Computed in the grid (sum / avg / last per row `agg`) unless `payload.fy.rows[key]` supplies values. Not in the contract; optional for module agents.
10. **Login return (needs an orchestrator decision, only with the app's auth on).** The 401 redirect goes to `/login?next=/projection/...`; the existing SPA login then does a client-side `navigate(next)` and shows "Not found" until reload. A one-line fix in `app/static/app.js` is given in `MODULE_ui_shell.md` ("Known gaps"); not applied because that file is outside this agent's ownership beyond the nav link.
11. **Browser pane launch entry.** `.claude/launch.json` in the worktree defines `projection-ui` (python `tests/projection/ui/mock_server.py 5191`), but the Browser pane's `preview_start` only listed the entries from other folders (`lonvera-bfcm`, `tag-explorer`), so the pane was verified by starting the same command from Bash and navigating to `http://127.0.0.1:5191`.
