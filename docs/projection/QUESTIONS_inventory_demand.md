# Questions and assumptions (inventory_demand)

1. **Grid vocabulary.** `Table` / `Row` in `app/projection/interfaces.py` validate `kind` in `line|subtotal|total|header|memo` and `fmt` in `money|int|num2|pct1|...`, while the shared grid (`grid.js`, `format.js`, `MODULE_ui_shell.md`) reads `kind: input|calc|subtotal|total|header|ratio` and `fmt: usd|usd0|pct|num|x|text|date` (`money`, `int`, `line`, `memo` fall through to plain number formatting with no indent). Default chosen: this module builds its payload dict directly in the grid's vocabulary. If core normalizes in `Table.to_payload`, nothing here needs to change; money modules will hit this first.
2. **`today` for modules.** `engine.run(..., today=)` is not passed to a module's `compute`, and `reconcile.py` does not pass it either. Default chosen: the module resolves its forecast date as scenario param `inventory_demand.as_of`, else env `PROJECTION_TODAY`, else today in Pacific time. Run the final reconcile with `PROJECTION_TODAY=2026-11-03`; any module that rolls with `TODAY()` in the sheet will need the same.
3. **Per-module reconcile in a partial database.** `reconcile.py` runs `engine.run(strict=True)`, which executes every built module, so a database holding only one module's tables fails on the first other module. Default chosen: verified with a scratch wrapper that calls the same `reconcile` functions with `engine.run(package=<only this module>)`. A `--package` option on `reconcile.py` would make `--module <key>` work in an isolated database.
4. **Amazon `stale_after_days` is 2, not 4.** The freshness hook reports the newest complete day stored. Amazon now comes from `Amazon - Product Daily` (fresh through yesterday), so 2 is right; the older tab it replaced would have needed 4 (two held-back days). If Product Daily is unreadable and the fallback tab is used, the feed shows stale honestly.
5. **Stock table.** `inventory_supply` owns the editable stock snapshot. This module also lands the US warehouse's on hand and allocated into `proj_demand_snapshot` on every refresh (the coordinator asked for it); supply may read the latest `as_of` per product from it if it wants Revamp stock to follow the feed.
6. **Sheet range reads.** `live_reader` reads `A1:Z` of each tab; the Amazon tab holds about 1,730 rows today (1,100-day rolling window, three products), well inside the 10 million cell limit.
